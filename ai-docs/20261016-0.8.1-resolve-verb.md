# 0.8.1：图库不再有「推送到云端」「重新上传」——没同步好的文件只有一个动作「处理…」→ store `file.resolve()`

> created 20261016 by Claude Fable 5.1 · as-of 0.8.1 · patch（修的是不合法的动词，不是新功能）。user 2026-10-16：「存档管理里"云端没了/从未上传"这类行目前只有「传上去」一个选项…是UX在逼我，然后为什么这里还是越狱了，这个按钮原则上应该compile error」「因为这个动词一开始就不合法，不在词汇表上」「这个按钮为什么能存在是更大的安全问题」→「gallery 的「推送 / 重新上传」要不要同样收进词汇表…同意」「全量改」。

## 行为差异（和 0.8.0 比）

- 卡片菜单里 `dirtyBoth` / `conflictBoth` / `localOnly` / `float` 行的「推送到云端」、`pendingGone` 行的「重新上传」**全部换成一个「处理…」**（`verbs.resolve(item)`）。它调 store 0.18 的 `file.resolve()`：库先看云端那一侧（已变 / 没了 / 没变 / 从没有过），再经 `ui.resolveConflict` 问人三选一——**云端覆盖本地 / 本地覆盖云端 / 取消**。云端没了 / 从没有过时选「云端覆盖本地」= 这份进回收站（可恢复），选「本地覆盖云端」= 传上去。
- `verbs.push` / `verbs.reupload` 从动词表删除；`VerbFile.reupload` 换成 `VerbFile.resolve`。宿主传真 store（0.18.x）即可，不用改适配层；`VerbDoc.open` 变成可选项（处理的是正在打开的那份、换了世界线时让宿主重开）。
- 冲突面措辞按 `cloudState` 换：云端没了 / 从没有过 → 标题「云端没有这份」+ 对应正文；云端没变 → 「云端还是上次同步的那一版，本机有新改动没上传」。三个按钮和主按钮（云端覆盖本地）不变。
- 字符串：删 `gal.pushCloud` `gal.reupload` `gal.busy.reupload` `gal.st.reupload*`；加 `gal.resolve` `gal.busy.resolve` `gal.st.resolve.*` `cf.cloudGoneTitle` `cf.body.absent/never/unchanged` `st.fileUploading`。
- 依赖：`@internal/store` ≥ 0.18.2（`resolve()` + `cloudState`）；本包钉 0.18.4。

## 为什么是 patch

0.8.0 的动词里「推送到云端 / 重新上传」替人定了方向（本机赢），和库的「冲突必由人在面里选」直接矛盾——这是修 bug，不是加功能；词汇表之外的动词在图库里本来就不该存在。
