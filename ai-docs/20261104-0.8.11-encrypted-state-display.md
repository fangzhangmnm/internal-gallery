## 1. 两个洞（0.8.10 的行为）

1. **锁图标和加密菜单**：卡片的 `encrypted` 只看「本地字节是不是加密容器」，而且按名字探一次就永远记着（`encByName`）。所以：
   - 纯云端、这台从没开过的加密件：本地没字节 → 显示成没加密（锁不亮）。
   - 这台探过「不加密」的一份，别的设备把它加密了、这台快进拿到了容器 → 还是显示没加密，⋯ 菜单还给「加密…」不给「解除加密…」。
2. **旧明文封面**：A 设备加密了一份，B 设备缩略图缓存里加密之前那张明文封面要等图库列到那张卡、拉到新字节才被覆盖；云端不可达时缓存层「退旧图」把它照样显示出来。回收站里的加密件同样会退回显示同名的旧明文图。

## 2. 改了什么

**判定只有一处**：新文件 `src/core/model/encryption-state.ts`（不出包门牌）。

- 加密态 = **取或**，每一路都是 store / 加密端口给的事实，图库不看字节内容：
  - 本地那一路：宿主 `encryption.isEncrypted(identifier)`（→ store `file.isEncrypted`，纯本地读头）。
  - store 的 peek 那一路：缩略图格子拿到的是 store 打了 `ENC_PEEK_MIME` 的密文 peek（宿主 `encryption.isEncryptedPeekBlob` 认）——现拉的、缓存命中的、拉不到退回来的都算。格子 `emit("sealed")` 报给图库。
  - 回收站 / 备份箱卡片：store 的 `TrashItem.encrypted`（云端名带 `.zip`）——0.5.0 起就在 `AsideItem.encrypted` 上，这版把它也递给格子。
- **结论绑版本戳**（syncState + 修改时间 + 大小）。版本变了 → 本地那一路重探（重探完之前沿用上一版的结论，免得锁闪一下），peek 那一路作废、等格子按新版本重拉。本地没字节的记「本地这一路不说加密」。
- 本地探测改成串行：一趟在探时又来新帧 → 这一趟完了按最新列表补一趟（防旧版本的结论晚到盖掉新版本的）。

**卡片**（`src/ui/gallery-screen.ts` + `src/ui/templates.ts`，模板已重编）：

| | 0.8.10 | 0.8.11 |
|---|---|---|
| 锁图标、卡片 `encrypted` class | 本地字节（探一次） | 加密态（取或、按版本） |
| 本地解密封面那条路（`encName`）、「解除加密…」 | 本地字节 | 本地字节（按版本重探） |
| 「加密…」 | 有本地字节 ∧ 本地不是容器 | 有本地字节 ∧ **不是已知加密** |
| 云端已加密、本地还是旧明文（没快进） | 给「加密…」 | 两项都不给（加密会推出和云端分叉的容器；解除会被 store 回「这不是加密作品」） |
| 格子拿到明文图 | 显示 | 已知加密 → **不显示**（不管现拉、命中还是退回来的旧图）；已经显示着的当场撤掉 |
| 缓存里加密之前的明文封面 | 等格子重拉才覆盖 | 一知道这份（这一版）加密就删（`dropPlainByproducts`：只删明文图，密文 peek 留着；每份每版一次） |
| 卡片事实（`policy.facts`） | 加密件不取，但内存 / IDB 里明文时代的值还在、还递给宿主画 | 已知加密 → 不递给 `tileOverlayHtml` / `tileAction`；IDB 和内存里的值删掉 |

卡片事实不在派单里，是同一条规矩、同一个机制（加密件本来就不取事实，留着的都是明文时代的），一起做了；Fable 不要可以只撤 `dropPlainByproducts` 里 facts 那几行。

## 3. 没做到的：活文件「云端名带容器后缀」这一路，store 没给

派单写的是「云端名带容器后缀 → 库能认」。查下来：**store 列举出来的 `Item`（2.1.2 到 2.2.5）只有 identifier / syncState / size / lastModified / kind / tier**。云端名在 store 里经 `identifiers.fromCloud` 变成身份时 `sealed` 那一位被丢掉了（`create-store.ts` 的 `toName = (cloudName) => ids.fromCloud(cloudName).identifier`），图库拿不到；拿云端名本身也不行（家规：全走库，不碰云）。

所以这一版**仍然盖不住**的：

- **纯云端、这台从没开过、种类又没有密文 peek 的加密件**——CatsUp 的 `.glb` / `.catsup` 正是这种（store `getHead` 对加密件回 null，宿主当「未知」抛）：第一次打开前锁仍不亮。（这种件卡片菜单本来就不给加密两项——要本地字节——所以菜单那一半没有差别。）
- **A 加密、B 还没快进、云端又不可达**：B 不知道它加密了（本地还是明文、peek 拉不到），旧明文封面照样退回显示。B 本地的字节此刻也还是明文。快进之后本地那一路认出来，缓存当场删。

补法（要 Fable 定、改的是 store）：store 在 `Item` 上带出云端那一份是不是容器（例如 `sealed?: true`，值来自 `fromCloud` 已经算出的那一位），图库把它当第三路接进 `createEncryptionState`（一行）+ 一条测试。要不要做、字段叫什么、store 走 patch 还是要 user 批，都不是本单能定的。

## 4. 公开接口

签名零变化（`api/gallery.d.ts` diff 只有 `GalleryTile.encrypted` 多了一段说明）。语义变了一处：`GalleryTile.encrypted` 从「本地字节是容器」变成「加密态（取或）」——宿主拿到的 `TileInfo` 里没有这个字段，宿主自己调 `tileFor` 的不受影响（注入什么就是什么）。`GalleryHandle.invalidateEncrypted` 照旧（= 忘掉这一份、重探）。
